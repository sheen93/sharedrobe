# 08-definition-of-done.md

## Objective
Establish the absolute minimum quality threshold before an agent reports a task as complete. A project is not done just because the main code exists[cite: 33].

## Universal Minimum Completion Standard
Work is incomplete unless it provides:
*   Clear objective and scope[cite: 33].
*   Recommended stack with reasoning[cite: 33].
*   Project structure[cite: 33].
*   Full implementation for the requested scope[cite: 33].
*   Dependency installation steps[cite: 33].
*   Environment variables list[cite: 33].
*   Local run instructions[cite: 33].
*   Testing guidance[cite: 33].
*   Deployment guidance[cite: 33].
*   Notes on future improvements[cite: 33].

## Frontend Completion Checklist
*   Responsive layout works on mobile and desktop[cite: 33].
*   Accessibility basics are covered[cite: 33].
*   Loading states, empty states, and error states are present/handled[cite: 33].
*   Forms are validated[cite: 33].
*   Navigation works properly[cite: 33].
*   UI is reasonably polished[cite: 33].

## Backend Completion Checklist
*   Routes or endpoints are defined clearly[cite: 33].
*   Validation and error handling are included[cite: 33].
*   Database models or schema are defined clearly[cite: 33].
*   Auth flow is explained if relevant[cite: 33].
*   Env variables are documented[cite: 33].
*   Deployment steps are included[cite: 33].

## Product Quality Validation
*   The solution solves the stated problem and the scope matches the product stage[cite: 33].
*   The architecture fits the use case[cite: 33].
*   Important missing features are identified[cite: 33].
*   Risks and tradeoffs are pointed out[cite: 33].
*   Useful next steps are suggested[cite: 33].

## Final Delivery Expectations
*   The answer should help the user build immediately[cite: 33].
*   The implementation should be practical[cite: 33].
*   The guidance should reduce guesswork[cite: 33].
*   The result should feel like a senior engineer prepared it[cite: 33].
