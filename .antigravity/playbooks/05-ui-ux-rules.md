# 05-ui-ux-rules.md

## Objective
Guide design agents and frontend engineers to build zero-friction interfaces by default[cite: 30]. 

## Core Design Mindset
*   Design for clarity first[cite: 30]. Make interfaces feel modern, clean, and practical[cite: 30].
*   Prefer intuitive user flows over flashy design[cite: 30].
*   Every screen should help the user understand what to do next[cite: 30]. Reduce friction wherever possible[cite: 30].

## UX Priorities
*   Make the main action obvious and reduce unnecessary steps[cite: 30].
*   Keep navigation simple and group related information clearly[cite: 30].
*   Use progressive disclosure when complexity is high, and avoid overwhelming users with too much at once[cite: 30].

## UI Expectations & Visual Hierarchy
*   The UI should look polished and production-ready[cite: 30].
*   Use consistent spacing, typography, and visual hierarchy[cite: 30].
*   Prefer clean layouts over cluttered ones, utilizing a limited, intentional color palette[cite: 30].
*   Prioritize readability and alignment[cite: 30]. Keep components visually consistent[cite: 30].

## Responsive & Accessible Design
*   **Responsiveness:** Design mobile-first when practical. Ensure layouts work well on phone, tablet, and desktop. Avoid fragile layouts that break at common screen sizes. Buttons and touch targets should be easy to use on mobile. Navigation should adapt clearly across devices[cite: 30].
*   **Accessibility:** Use semantic HTML where relevant. Ensure reasonable color contrast. Include labels for form inputs. Support keyboard navigation where relevant. Avoid relying only on color to communicate meaning. Write helpful empty states, validation messages, and errors[cite: 30].

## Forms & User Flows
*   **Forms:** Keep forms as short as possible, asking only for information that matters. Use clear labels and placeholders when helpful. Show validation errors clearly, prevent confusing states, and make submit actions obvious[cite: 30].
*   **Flows:** Think through the full user journey (onboarding, core use, edge cases, return visits). Include loading states, empty states, success states, and error states. Make important actions easy to find and reduce dead ends in navigation[cite: 30].

## Implementation Constraints
*   **Frontend:** Build reusable components, keep styling scalable and organized, use consistent spacing/patterns, avoid mixing too many styles/visual systems, and prefer maintainable design systems over one-off styling[cite: 30].
*   **Websites:** Prioritize clarity, conversion, performance, and SEO. Make the value proposition obvious near the top, use clear calls to action, structure pages for quick scanning, and make layouts appealing without sacrificing clarity[cite: 30].
*   **Web Apps:** Prioritize usability, speed, and clarity. Dashboards should surface important information first. Navigation must be predictable. Tables, filters, and forms should be easy to use[cite: 30].
*   **Mobile Apps:** Respect platform conventions, keep actions thumb-friendly, minimize typing/repeated steps, make loading/sync behavior clear, and keep navigation familiar[cite: 30].

## Agent UI/UX Intervention Behavior
When helping build UI or UX, agents must:
1.  Improve rough ideas into better user flows[cite: 30].
2.  Suggest better layouts and interactions[cite: 30].
3.  Point out friction, confusion, or weak design choices[cite: 30].
4.  Recommend practical UI improvements, not just aesthetic changes[cite: 30].
5.  Default to clean, modern, user-friendly design[cite: 30].
